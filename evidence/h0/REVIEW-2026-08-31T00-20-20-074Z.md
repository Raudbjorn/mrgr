# H0 adjudicator-replacement run — 2026-08-31T00-20-20-074Z

**Significance verdict: NULL.** Same as 2026-08-30, on a four-times-larger
coder-specialised model with grammar-constrained decoding and zero schema
failures. That is the point of this run.

## Why it was run

The 2026-08-30 run's null came with a caveat: its adjudicator was a 7B model
that produced 8 schema-invalid records, so "the model is too weak / too sloppy"
was a live alternative explanation for the null. This run removes that
explanation.

- Wall time 16m09s for 540 records (~4 s per LLM call), against a >2 h budget.

**This is a different experimental condition from 2026-08-30 — different model
AND grammar-constrained sampling. The two runs must not be pooled.**

## What this establishes

The 2026-08-30 null could be read as a statement about a weak 7B adjudicator.
It cannot be read that way now. Quadrupling the parameter count, switching to a
coder-specialised model, eliminating every schema failure and every halt moved
the correct counts up by 15–100% — and moved `arm_only` not at all, because
`arm_only > 0` is unreachable under this grader (see
`SIGNIFICANCE-2026-08-30T02-54-42-056Z.md`, "The ceiling"). Constant
`compose` is the union of `keep_ours` and `keep_theirs` once
`isHistoricalMatch` strips whitespace, so it upper-bounds every arm by
arithmetic.

Two adjudicators, four times apart in size, one constrained and one not, both
land on `arm_only = 0`. The structural argument now has an empirical
demonstration attached.

**This does not reopen WP8.** WP8's single reopen condition is a fixed grader
plus a re-run that clears the gate. This run has a better adjudicator and the
same unpassable gate.

## The one flagged citation is a parser bug, not fabrication

`selected`, triple `6756473cca7b`, run 2 emitted:

```
[source:ours:parser.gen.c, source:ours:parser.gen.h]
```

Two citations inside one bracket. `parseDecision`'s regex
`/\[source:([^\]]+)\]/g` captures the comma-joined pair as a single id,
which then matches nothing in `evidence_ids_exposed`. **Both parts are in
`evidence_ids_exposed`.** This is the same formatting class as the three
records reviewed on 2026-08-30 — now reproduced on a completely different
model, which makes the parser, not the model, the clear culprit. The
mechanical `verdict: invalid` in this run's aggregate stands as computed;
`significance_verdict: null` is the acceptance-gate outcome and is unaffected
either way.

Actionable: split on `]` boundaries *and* on `, source:` inside a bracket
before set-membership. Not done here — changing the fabrication check mid-
analysis is the kind of moving target this corpus exists to prevent.
