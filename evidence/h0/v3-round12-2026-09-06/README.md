## Extraction throughput repair

The first exact-blob extractor spawned one Git process per file. In `blob:none` partial clones, this also triggered individual network fetches. The [Git partial-clone documentation](https://git-scm.com/docs/partial-clone) describes that cost and bulk prefetching of missing objects. The acquisition helper now enumerates missing objects for the requested commit, fetches them together, and reads exact blobs through bounded `cat-file --batch` groups. It preserves the existing per-blob size limit, validates every output header and byte length, writes symlinks last and retains containment checks. The behavioral instrument and effect thresholds are unchanged.

The first batching-only [preflight failed](batching-first-preflight-failure.json) while requesting sizes from a partial clone. That failure and source are retained. The corrected [preflight](batched-extraction-preflight.json) extracted 1,752 tracked files in about 1.36 seconds and independently checked every Git blob hash and file mode. The mirror was already partly populated; this is not a cold-download benchmark or a claimed speedup ratio. [Regression checks](batched-extraction-checks.txt) cover ignored/substituted files, binary content, executable modes, symlinks, multiple batches and a partial clone with genuinely missing objects.

Screens already running keep their original loaded implementation. [Per-screen source provenance](screen-source-provenance.json) identifies the version each uses. Five Caddy/Echo/Micro cases that stopped with Git extraction timeouts before test execution are re-screened in separate directories with the repaired helper. Their initial receipts remain preserved; no model request or failed behavioral conclusion is retried.
