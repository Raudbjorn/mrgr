# H0 independent review — 2026-08-27

Reviewer verdict: **the "positive" verdict does not stand.** Not "weak"; not "small-n".
Invalid. Five independent defects, any one of which is disqualifying.

## D1 (fatal) — ground truth is in the prompt, every arm

`_h0_runner.ts:71` — `hunkOnly` string, used by ALL three arms:

```
`<<RESOLUTION_HINT>>\n${triple.resolution}<<END_RESOLUTION>>\n`
```

`triple.resolution` is the developer's merge resolution — the exact string
`_aggregate.ts:isHistoricalMatch` grades against. The model is handed the answer
key and asked to name it. This is not adjudication under evidence; it is a
label-reading task. Nothing about "evidence utility" can be inferred.

## D2 (fatal) — the full-bundle arm does not contain a preimage

`_h0_runner.ts:84-85`:

```
`<<FILE_FULL_PREIMAGE (ours side)>>\n${trim(triple.ours)}\n...`
`<<FILE_FULL_PREIMAGE (theirs side)>>\n${trim(triple.theirs)}\n...`
```

`triple.ours` / `triple.theirs` are **conflict-region text** (median a few hundred
chars; see triples-*.jsonl), not file preimages. The arm therefore shows the same
two strings twice, under a label that says "file full preimage", capped at 1200
chars. The mechanism the summary credits ("file preimage context") was never
delivered. Whatever the 2-triple delta is, it is a redundancy/prompt-position
artifact, not preimage context.

`triple.base` exists in every record (that was the point of the F1 diff3 fix) and
is passed to **no arm**, while SYSTEM_PROMPT tells the model "You will be shown a
git conflict (with a base, ours, and theirs side)."

## D3 (fatal) — every arm loses to a constant

Subsample (n=15), scored by the shipped grader:

| policy | correct |
|---|---|
| constant `compose` | **9/15** |
| grader ceiling (any label matches) | 9/15 |
| full-bundle | 6/15 |
| hunk-only / selected | 4/15 |

Full corpus (n=862): constant `compose` = 76.9%, `keep_ours` = 40.3%,
`keep_theirs` = 12.4%. No trivial baseline was run. The best arm scores 6/15
against a one-line heuristic that scores 9/15 and simultaneously saturates the
oracle ceiling.

Cause: `isHistoricalMatch` is asymmetric. `keep_ours`/`keep_theirs` demand exact
whitespace-normalised equality with the resolution; `compose` passes on >=1
shared line of length >3 with each side. The metric largely measures "did it say
compose".

## D4 — n is 15, not 45; p = 0.70

`temperature: 0.0` (`_h0_runner.ts:104`). Per-run correct counts are identical:
hunk-only {4,4,4}, selected {4,4,4}, full-bundle {6,6,6}. The 3 repeats are the
same decision copied three times; the aggregator sums them as 45 independent
trials. "3-of-3 agree 15/15" is a property of temp=0, not a stability finding.

Real effect: 4/15 -> 6/15, i.e. **2 triples flipped**. Fisher exact two-sided
p = 0.700. The headline "reduces wrong-decisions by 6/45" is the same two triples
counted three times each.

## D5 — the verdict was close to pre-determined

`_aggregate.ts` kill condition:

```ts
const h_w_halt_ratio = hunkOnly.halt > 0 ? hunkOnly.wrong / hunkOnly.halt : Infinity;
if (h_w_halt_ratio < 1 + EPSILON && inNoise) killConditionMet = true;
```

`halt === 0` in all arms, so the ratio is `Infinity`, so `killConditionMet` is
**structurally unreachable**. Reporting "kill condition met: false" conveys zero
information — it could not have been true.

With the kill branch dead, the fallback is
`selected.wrong < hunkOnly.wrong || fullBundle.wrong < hunkOnly.wrong` -> "positive",
with no magnitude and no significance threshold. A single flipped triple in either
of two arms yields "positive".

## Secondary

- `corpus_size: 862` (aggregate) vs "898 exact triples" (corpus.json / summary).
  898 is a line count; 22 duplicate `triple_key`s (all intra-file) -> 862 unique.
  The summary's 898 is wrong as a unique-triple count.
- `seed_subsample: 30` is a hardcoded literal in the aggregate doc. Actual n is 15:
  `subsample()` returns all items when `items.length <= n`, and only 15 triples
  passed `isSmallTriple` (<=2400 chars). The doc reports a parameter, not the n.
- `fabricated_ids` is `reason.match(/\[source:([^\]]+)\]/g).length > 0` — it flags
  **any** citation, with no check against real ids. "fabricated_evidence_ids: 0"
  for `selected` means that arm emitted no `[source:]` tags at all. The field is
  misnamed and unusable as a hallucination metric.
- `selected` arm's DEPENDENCY_LIST is the hardcoded literal
  `"(none — single-file conflict)"`. No dependency computation ever ran. The claim
  "the dependency list was empty in 100% of trials — every conflict was
  single-file" is not a measurement; it is a string constant.
- `subsample()` is stride-based over file-concatenation order (jq then cli), not
  randomised. Moot at n=15 (all pass through), but it is not a random sample.
