### 3.4 H0 — evidence-utility discriminator

- **Verdict, in two words: VALID and NULL.** The run is clean; the hypothesis did not hold. Keep the two separate — conflating them is how the 2026-08-27 run went wrong in the other direction.
- **Closed gates:** the frozen sample is 30 triples stratified as 10 jq + 10 cli + 10 redis, spanning three repositories and two languages (C and Go). The corrected PRNG produced the intended stratification. The updated adjudicator was reachable and model identity matched the measured GGUF SHA. Resume and same-stamp replay were deterministic at the record-file level.
- **Machine verdict INVALID; reviewed verdict VALID — these are not the same claim, keep them separate.** `_aggregate.ts`'s any-flag fabrication rule mechanically fires on this run (`selected`: 2 records, `full-bundle`: 1 record cite a `[source:<id>]` tag outside that record's own `evidence_ids_exposed`) and the code honestly computes `verdict: "invalid"`, `run_valid: false` — preserved as-is in `evidence/h0/aggregate-2026-08-30T02-54-42-056Z.json` (**corrected 2026-08-30**: that file's verdict fields were briefly hand-edited to say valid/true without updating `verdict_reason`, which was self-contradictory; reverted to match what the code computes). **Human review (2026-08-30) overrides that machine verdict to VALID**: the three flagged citations are non-canonical **citation-tag formatting** (leading-space source tags, one bare `[source:ours]` structural-label citation) rather than genuine references to evidence outside what the record's prompt exposed — see `evidence/h0/INVALIDATION-RULE.md`'s "Recorded exception (2026-08-30)" for the standing record of this override, and `evidence/h0/REVIEW-2026-08-30T02-54-42-056Z.md` for the full reasoning. The reviewed verdict (VALID) is what's operative for WP8 gating below. No corpus-diversity, language-spread, PRNG, model-pin, or adjudicator-availability gate remains open. Schema-invalid records were observed (4 hunk-only, 3 selected, 1 full-bundle) — see WP3's acceptance-gate note in `work-packages.md` for whether that needs its own policy.
- **Acceptance gate EXECUTED 2026-08-30 — verdict NULL.** The Fisher-exact/paired significance test that `redesign-requirements.md` (§7 item 5) and `work-packages.md` (WP4) specify was never run on this data until now. It has been run: McNemar's exact two-sided test on per-triple binary vectors (the unit §7 item 4 requires), α = 0.05, against the best trivial baseline (`baseline-compose`, 9/30 triples). Fisher exact is reported as the unpaired cross-check. **No arm passes**: hunk-only 7/30 (Δ −2, p = 0.50), selected 8/30 (Δ −1, p = 1.00), full-bundle 4/30 (Δ −5, p = 0.0625). Stronger than "no arm passes": `arm_only = 0` at both the triple and record unit — **every conflict a model arm resolved correctly, the constant also resolved correctly.** The only significant result is full-bundle being *worse* than a constant (record-level p = 0.0001). Full detail and reproduction: `evidence/h0/SIGNIFICANCE-2026-08-30T02-54-42-056Z.md`.
- **The gate was unsatisfiable by construction — record this alongside the null.** `_aggregate.ts`'s `isHistoricalMatch` normalizes with `replace(/\s+/g, "")`, stripping newlines, so its shared-line overlap test for a composed resolution degenerates to string equality. `compose` is then correct exactly when `keep_ours` or `keep_theirs` is — their union — making constant `compose` a mathematical upper bound on every arm, for any corpus. Verified exhaustively (`packages/core/tests/m1a/h0-evidence-scripts.test.ts`, "grader ceiling"). On this corpus the developer's resolution matches a side verbatim on 9 of 30 triples; **the other 21 are unwinnable by any decision in `{keep_ours, keep_theirs, compose, halt}`.** So the null does not license "evidence-conditioned adjudication fails" — the instrument could not have shown that it works. This is the same class of unreachable gate `reference/self-attack.md` records as fixed: it was removed from the kill rule and left in the grader.
- **Corroborated 2026-08-31 on a stronger adjudicator — this rules out malformed output as the explanation, and nothing more.** The 2026-08-30 null could be read as "the 7B adjudicator was too sloppy" (it produced 8 schema-invalid records). That specific reading is now closed. **It does not establish that model capability is irrelevant, and it cannot:** under the current grader 21 of 30 triples are unwinnable by any decision in the enum and `arm_only = 0` is guaranteed, so the null stays non-diagnostic about capability no matter which adjudicator produces it. A stronger model scoring the same is consistent with the ceiling, not evidence against capability mattering. A rerun on the same 30 frozen triples with `Qwen3-Coder-30B-A3B-Instruct-UD-Q3_K_XL` (30.5B, coder-specialised, 4x the parameters) under grammar-constrained decoding produced **zero** schema-invalid records, **zero** halts on full-bundle, and correct counts up from 20/22/13 to 23/25/26 — and `arm_only` stayed **0** on every arm at both units. full-bundle now ties constant `compose` at 9/30 and never exceeds it; its 9 correct triples are the same 9. Two adjudicators four times apart in size, one constrained and one not, both land on `arm_only = 0`, because the grader makes that the only reachable value. See `evidence/h0/REVIEW-2026-08-31T00-20-20-074Z.md`. **This does not reopen WP8** — WP8's condition is a fixed grader plus a passing rerun, and this run has a better adjudicator against the same unpassable gate.
- **Reported, not binding — two favorable readings that do not close the phase.** (a) Wrong-count: full-bundle makes 49 wrong decisions to compose's 63, bought entirely by halting 27/90 times while being significantly worse on correctness. A policy that halts on everything scores `wrong = 0`; WP4's STOP rule names exactly this ("if forced resolution dominates halt at any plausible cost ratio"). (b) Break-even halt cost, on records valid in both arms: an arm is cheaper than `baseline-compose` when one halt costs less than 0.600 (hunk-only) / 0.583 (selected) / 0.481 (full-bundle) of one wrong merge. Plausible ratios — and all three are beaten by a halt-on-everything policy, which scores 0.700 on the same measure, so the ratios rank every arm below deciding nothing. That is why they are characterization. - **Citation accounting in both runs is a lower bound (found in PR #11 review).** `parseDecision` truncated `reason` to 400 characters before extracting `[source:...]` tags, while the decision schema allows 800. 52 records in the 2026-08-30 run and 215 in the 2026-08-31 run sit at exactly 400 characters, so tags past that point were discarded before the fabrication check saw them, and the untruncated text was never stored. The error is one-way — tags can be missed, never invented — so `fabricated_evidence_ids` is a floor and an invalidation could have failed to fire. `decision` is a separate field and is not truncated, so **correct/wrong/halt and the null verdict are unaffected**. Fixed forward in `_h0_runner.ts`; committed records left as produced.
