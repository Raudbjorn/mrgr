## The old gate could not establish evidence utility

The problem is stronger than the newline defect recorded in [current-state.md](current-state.md). In [`isHistoricalMatch`](../../../../evidence/h0/_aggregate.ts), `compose` first accepts every reference accepted by either side, then optionally accepts overlap. Therefore its success set contains the success set of every resolving action even if normalization preserves newlines. More cases or a stronger model cannot beat that constant. Removing a baseline or assigning it a different grading rule would conceal the defect.

The replacement [`v2.mjs`](../../../../evidence/h0/v2.mjs) grades concrete replacement strings identically for all arms. An output may match either side, a real Git union, a novel blend, or none of them. The primary endpoint is **exact agreement with the historical developer replacement, normalizing CRLF only**. Whitespace inside literals is preserved. This is an auditable measure of historical agreement, not a semantic correctness oracle. [Merge-Bench](https://arxiv.org/html/2605.25890v1) distinguishes matching, program equivalence, and finite test evidence; the new instrument preserves that distinction.

## Frozen intervention and decision contract

The active [protocol](../../../../evidence/h0/v2-2026-09-06b/protocol.json) and its exact [source snapshot](../../../../evidence/h0/v2-2026-09-06b/instrument.mjs) are the execution contract.

| Item | Frozen choice |
| --- | --- |
| Population | Small, authored, exact-localized C/Go conflicts in cli, Redis, and libgit2; both parent paths exist; each side has a unique nonempty hunk occurrence |
| Unit | One conflict per merge, all arms paired on the same case; duplicate content keys excluded across repositories |
| Split | 8 development cases per repository; confirmation: 40 cli + 26 Redis + 26 libgit2 = 92 merge cases |
| Hunk-only | Base, ours, theirs, language and path |
| Selected, primary | Same hunk plus up to 1,800 UTF-16 code units around each parent's hunk and both parent commit subjects |
| Bounded context, ablation | Same hunk and subjects, up to 5,000 UTF-16 code units per parent; explicit window offsets, original byte counts and truncation flags |
| Output | JSON: resolve/halt, concrete replacement string, exposed source-ID citations; no free-form correctness claim |
| Baselines | Keep ours; keep theirs; actual `git merge-file --union --diff-algorithm=myers` output; longer side with ours on ties; always halt |
| Model | Pinned Qwen3-Coder-30B-A3B GGUF, actual SHA verified; isolated llama.cpp build 9827; one request per case/arm, temperature 0, fixed seed, 768 output-token ceiling |
| Denominator | Every scheduled case; invalid output, timeout and halt all contribute zero historical matches and retain costs |
| Infrastructure validity | At least one valid response per arm; no more than 5% transport failures per arm; valid development preflight before confirmation |
| Positive gate | Selected improves historical-match yield by at least 5 percentage points **and** has exact paired two-sided McNemar p < 0.05 against hunk-only **and every baseline** |
| Negative/inconclusive gate | A valid completed run that fails the positive conjunction records no demonstrated superiority; it closes Phase 3 without asserting equivalence |

This is a new **local-context-plus-parent-subjects policy**. It does not validate the old filename selector, a dependency graph implementation, arbitrary issue/commit retrieval, an agent adapter, or semantic safety. Bounded context cannot rescue a failed selected primary by becoming the winner after inspection. The five-point threshold is a project decision, not a literature-mandated standard. A significant improvement with an observed five-point magnitude does not establish that the population effect exceeds five points.

The hypothesis is the paired difference in historical agreement when adding this specified evidence policy to the same adjudicator. The pooled estimand weights repository strata 40:26:26, matching the frozen cases, rather than giving each repository equal weight. Pairing controls the case/model configuration. Context content and token length change together: the experiment measures the policy as a whole and does not isolate relevance from length. Unknown shared-history dependence and pretraining contamination remain limitations.

## Evidence strength, uncertainty, and stopping

For paired binary outcomes, exact McNemar uses discordant pairs; the old unpaired Fisher cross-check is not a confirmatory alternative. [Dror et al., ACL 2018](https://aclanthology.org/P18-1128/) supports matching the test to paired outcome structure. Multiple hunks or temperatures do not create independent merge events. [Cameron and Miller, 2015](https://cameron.econ.ucdavis.edu/research/Cameron_Miller_JHR_2015.pdf) explains why within-cluster dependence can overstate precision, especially with few clusters. Here inference is conditional on three named repositories and assumes independence of sampled merge events within them.

The [prospective design calculation](../../../../evidence/h0/v2-2026-09-06b/design-check.json) enumerates the frozen magnitude-plus-significance rule. Under independent paired outcomes, its per-comparison positive probability at n=92 is about 1.5% under zero gain and 30% discordance; about 11% for a 5pp gain at 25% discordance; 34% for a 10pp gain at 30% discordance; and 70% for a 15pp gain at 30% discordance. These are assumed scenarios, not observed effects. Passing all comparisons jointly is harder. This study can reveal large gains; a failure cannot rule out a useful small gain.

For a larger future study, approximately 234 independent pairs provide about 78% exact per-comparison power for a 10pp gain at 30% discordance with this rule. A normal approximation suggests roughly 783 pairs for detecting 5pp at 25% discordance, before clustering, exclusions, joint comparisons or a stronger lower-bound claim. Additional prospective collection is justified if excluding small benefits becomes the decision. It is not permission to extend the present run until it passes.

The original thirty cases and the first interrupted development pilot are diagnostic only. Development identified a citation-contract defect: supplied hunk sides were uncitable, disproportionately invalidating hunk-only output. The revised common source contract admits base/ours/theirs and grammar-constrains citations to exposed IDs. Raw source sections also replace unnecessary JSON-escaped source presentation. The same development cases can be used to test the fix; no confirmation response preceded this amendment. [Cawley and Talbot, 2010](https://jmlr.org/papers/v11/cawley10a.html) motivates separating such selection from evaluation.

Coverage, historical disagreement among accepted outputs, correct yield, halt/invalid rates, token counts and latency remain separate. Always-halt has zero coverage and undefined selective risk. [El-Yaniv and Wiener, 2010](https://jmlr.org/papers/volume11/el-yaniv10a/el-yaniv10a.pdf) supplies the risk/coverage distinction. Break-even halt costs are descriptive because the project has no independently justified deployment loss ratio. Historical disagreement must not be relabeled a measured dangerous-merge rate.

Behavioral safety needs another evidence level: reconstruct runnable parent environments, validate conflict-specific assertions against deliberately wrong candidates, apply resolutions without unrelated historical-merge edits, and retain both test outcomes and blinded human judgments of alternatives. Zero errors in 30 independent accepted cases still permits a one-sided 95% error bound of about 9.5%; a below-1% bound with zero errors requires at least 299 independent accepted cases. These binomial calculations are not valid substitutes for accounting for clustering or inadequate tests. Neither new data counts nor a green historical-match result proves Phase 5.

## Tests that make the instrument reviewable

The [`v2.test.mjs`](../../../../evidence/h0/v2.test.mjs) check exercises real concrete baselines and both decision branches; literal whitespace preservation; exclusion of reference fields from prompts; rejection of invented citations; paired-test values; full aggregation of matched/nonmatched/halt/invalid cases; request/raw-output consistency; transport failure validity; and rejection of missing records. It uses Node's built-in test runner and is included in `pnpm test` and CI. No new project dependency was added.

Every run record stores the actual request and raw response. Aggregation reconstructs the request, reparses the raw response, verifies protocol/input/reference/instrument hashes, and requires the full case matrix. Raw corpus hashes are recorded as provenance; aggregation does not reopen those raw scans. Atomic per-record writes plus an exclusive runner lock support resume without changing an already recorded outcome. The archived instrument permits replay without silently reinterpreting old records under new code.
